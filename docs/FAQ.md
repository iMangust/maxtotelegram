# Частые вопросы (FAQ)

## Почему бот видит не все мои сообщения? Можно ли читать ВСЁ, без добавления бота в чаты?

**Коротко: нет, это невозможно ни через официальный API MAX, ни через наш мост.**
Это ограничение платформы, а не недоработка приложения.

### Как устроен API MAX (dev.max.ru)

MAX предоставляет только **Bot API** — то же самое, что Telegram Bot API:

1. Токен выдаётся конкретному **боту** (создаётся через @maxid / via.messapp),
   а не вашему личному аккаунту. Термин «токен сессии пользователя» из
   предыдущих обсуждений был неточным — пользовательских токенов-сессий
   публичный API MAX не имеет.
2. События (`message_created` и др.) приходят **только из тех диалогов,
   где бот состоит**:
   - личное сообщение человеку бот **не увидит никогда** — события
     прилетают только если пишут *самому боту*;
   - в групповой чат нужно **добавить бота** (один раз, на 5 секунд);
     после этого он получает все новые сообщения чата.
3. Ограничения long-polling по данным maxapi 1.2.3 / docs-api:
   ~2 запроса/сек, батч до 100 событий, TTL событий 24 часа — старые
   сообщения при простое бота теряются.

### Что происходит, если пишет «новый человек», с которым вы не общались

Такое сообщение приходит в ваш личный диалог в MAX, где нашего бота нет, —
и поэтому оно **не может быть переслано**. Как только вы ответите этому
человеку (или перешлёте ему любой контакт), вы можете добавить бота в диалог,
и дальнейшие сообщения уже будут дублироваться.

### Единственный легальный способ «пересылать всё»

Добавьте бота один раз во все чаты, которые вас интересуют. Дальше ничего
делать не нужно: новый человек, который напишет вам лично, останется зоной,
недоступной для Bot API любого мессенджера.

### А если использовать «userbot» (неофициальный клиент под вашим логином)?

Технически userbot читал бы все ваши диалоги, но:

- у MAX **нет публичного пользовательского API**; reverse-engineered клиенты
  нарушают условия использования сервиса;
- такие решения ломаются при каждом обновлении и часто приводят к
  **блокировке аккаунта**;
- поддерживать такой код в этом проекте мы не будем.

## Как добавить бота в чат MAX (30 секунд)

1. Откройте чат → «Информация о чате» → «Добавить администратора/участника».
2. Найдите вашего бота по username и добавьте его.
3. Готово: следующие сообщения из этого чата появятся в Telegram
   (команда `/chats` в Telegram показывает все чаты, откуда бот уже
   получает события).

## Уведомления о новых личных сообщениях

Пока человек пишет вам лично и бота в диалоге нет — уведомления не
приходят никак. Рекомендуем включить push-уведомления самого MAX для
личных сообщений, а дублирование в Telegram использовать для групповых
чатов и диалогов, где бота удалось добавить.

## Почему в Telegram такое возможно, а в MAX — нет? (api_id / api_hash)

Частый вопрос: «в Telegram же есть userbot'ы по `api_id`/`api_hash`,
которые читают всю мою переписку без добавления бота — почему так нельзя
в MAX?»

Дело в том, что у этих мессенджеров **разная архитектура API**:

| | Telegram | MAX |
|---|---|---|
| Bot API (`getUpdates`) | есть | есть — и это **единственный** публичный API |
| Пользовательский API | **есть, официальный** (MTProto): `api_id`/`api_hash` выдаются на https://my.telegram.org легально, под вашим аккаунтом работает полноценный клиент (Telethon/Pyrogram), видящий все ваши диалоги | **отсутствует** публично; токен сессии реверс-инжинирится из приложения, это нарушение ToS |
| Userbot | легален и поддерживается платформой | неофициальный, риск блокировки, ломается при обновлениях |

То есть в Telegram пересылка «всего личного» через `api_id` — это
не «лазейка», а официально предоставленный Telegram интерфейс клиента.
В MAX аналога нет: `dev.max.ru` отдаёт только Bot API, где события
доставляются исключительно боту и только по диалогам с его участием.

**Практический вывод:** если принципиально нужно дублировать в Telegram
*абсолютно все* входящие MAX-сообщения (включая личные от незнакомцев),
единственный технический путь — неофициальный userbot-клиент MAX
(реверс-инжиниринг приватного протокола). Мы сознательно не реализуем
это в проекте: такие клиенты нарушают условия использования MAX,
нестабильны и могут привести к блокировке вашего аккаунта. Безопасная
альтернатива — держать включёнными push-уведомления MAX для личных
диалогов и добавить бота во все нужные групповые чаты.

## «А может авторизоваться под своим аккаунтом и читать чаты списком?»

Коротко: публичного способа нет, а полулегальные эндпоинты Bot API для
этой задачи не подходят. Разбор по фактам (проверено на maxapi 1.2.3):

1. **Пользовательской авторизации в Bot API не существует.** Заголовок
   `Authorization` принимает только токен бота; методов входа по номеру
   телефона, QR-коду или обмену пользовательской сессии в
   `dev.max.ru/api` нет — это ровно та же модель, что и у Telegram Bot API
   (в нём тоже нельзя «залогиниться собой»).
2. **Эндпоинты чтения истории формально есть, но бесполезны для моста:**
   - `GET /chats` (`bot.get_chats()`) — помечен как **deprecated с июня
     2026**: «Готового списка чатов API не отдаёт ни через Long Polling,
     ни через Webhook — его нужно накапливать из событий». Он возвращает
     только чаты *бота*, а не ваши личные диалоги;
   - `GET /messages` (`bot.get_messages()`) — читает сообщения только в
     тех чатах, где бот состоит.
3. **Практический вывод:** даже если использовать эти эндпоинты, список
   «куда добавлен бот» мы и так получаем бесплатно из событий
   `bot_added`/`message_created` — наш мост уже накапливает их в SQLite,
   а `/chats` в Telegram показывает текущий охват. История же чужих
   личных диалогов через Bot API недоступна в принципе.

Таким образом, «авторизация пользователя» ничего не меняет: единственный
источник входящих сообщений — события боту по диалогам с его участием.
Полный охват личной переписки возможен только неофициальным userbot'ом
(см. раздел выше) — мы его сознательно не реализуем.


## Можно ли всё-таки читать личные сообщения без бота? (user-режим)

Да — начиная с текущей версии проект поддерживает **user-режим**: подключение
к вашему личному аккаунту MAX по WebSocket-протоколу веб-клиента web.max.ru
(`wss://ws-api.oneme.ru/websocket`, токен из Local Storage). В этом режиме
пересылаются ВСЕ входящие сообщения, включая личные от незнакомых людей,
без добавления какого-либо бота.

Реализация основана на протоколе проекта Aist/max2tg (см. файл NOTICE).

⚠️ Риски и ограничения user-режима:
* это неофициальный reverse-engineered протокол — нарушение пользовательского
  соглашения MAX, теоретически возможен бан аккаунта;
* токен `MAX_USER_TOKEN` даёт полный доступ к аккаунту — храните `.env`
  в секрете и не выкладывайте его;
* протокол может измениться без объявления — тогда потребуется обновление
  клиента;
* официальным и безопасным остаётся режим bot (`MAX_MODE=bot`).
